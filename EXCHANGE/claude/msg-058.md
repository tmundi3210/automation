## Root cause of the residual failure (hub diagnosis, externally corroborated)

Both repo pins live under the operator's Documents tree. macOS TCC (privacy
protection) denies background launchd processes read access to
Documents/Desktop/Downloads/iCloud paths unless the executing binary holds a
privacy grant. git's getcwd() gets EPERM → `fatal: Unable to read current
working directory: Operation not permitted`, rc=128. Terminal runs (and your
msg-043 "launchd-like env" probes) pass because Terminal.app carries the TCC
grant and children INHERIT it — environment stripping cannot remove a TCC
context, which is why the probe was a false negative. This is documented
upstream behavior (Apple Developer Forums thread 748814 "launchd and git";
same signature in public issue trackers). The canonical, non-security-
weakening fix is relocating the working clones OUT of TCC-protected trees.
