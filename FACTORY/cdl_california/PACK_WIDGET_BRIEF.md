# Widget build brief for the new packs (shared by all widget agents)

You are building topic-specific interactive teaching widgets for **CDL Workshop CA**, an offline Preact app that teaches the California CDL written tests (General Knowledge, Combination, and now Air Brakes AB, Doubles/Triples DT, Tank TK, Passenger PV, School Bus SB, HazMat HM) and the skills tests (SK). The app is at `FACTORY/cdl_california/app`. Your widget belongs to a NEW lesson in `FACTORY/cdl_california/source/packs/` (the original 18 are in `source/lessons/`); lessons are which are grounded in the CA Commercial Driver Handbook DL 650 (R12-2019). Handbook page text: `/tmp/claude-0/-home-user-automation/4f22bdf7-6382-586c-a88b-74190a187585/scratchpad/pdf/pages/<label>.txt` (e.g. `6-9.txt`).

## Hard rules
1. **Facts come only from the lesson file (and the handbook page it cites).** Every number, step, color, and rule the widget shows or checks must match the lesson text exactly. Read the whole lesson first. Do not use federal rules, websites, or memory. Where the lesson says "Handbook vs other sources", teach the handbook answer. Never teach anything marked "Beyond the handbook — not on the test" as a test fact.
2. **Only create files** in `app/src/widgets/w/` named `<your-widget-id>.tsx` (plus optional helper files named `<your-widget-id>.*.ts(x)`). Do NOT edit any other file. If you think a shared file needs a change, say so in your final report.
3. **Contract** (`app/src/widgets/registry.ts`): export `meta: WidgetMeta` and a default component `(props: WidgetProps)`. Look at the reference widget `app/src/widgets/w/gk01-class-finder.tsx` and copy its structure and styling approach.
   - `meta.anchor` is a RegExp matched against the lesson's concept titles; the first match hosts the widget. Concept titles for the new lessons are in `/tmp/claude-0/-home-user-automation/4f22bdf7-6382-586c-a88b-74190a187585/scratchpad/concepts_packs.txt`. Make sure your anchor matches the intended concept.
   - Two modes in every widget: **Explore** (manipulate freely, learn by doing; no scoring) and **Challenge** (untimed checks). Call `props.onEvidence({concepts: props.concepts, ok})` once per challenge answer. Call `props.onChallenge()` once when the whole challenge is completed with zero mistakes. Explore interactions must never call onEvidence. No timers, no lives/hearts, no points, no XP.
   - Give `meta.stamp` a topic-specific name (e.g. "Coupled clean") and a one-line rule.
4. **Pedagogy**: the mechanic must fit the topic (spatial → drag/place on a diagram; sequence → order steps with consequences; numbers → slider/calculator that shows the rule; systems → live schematic with state). Feedback explains WHY with the handbook reason, and cites the page with `<span class="plate">p. X-Y</span>`. Wrong choices show their consequence (e.g. trailer rolls, knob pops, rig tips) in text and visual.
5. **Visuals**: original inline SVG only (no images, no external URLs). Draw with the CSS tokens so both light and dark themes work: `fill="var(--surface-2)"`, `stroke="var(--ink)"`, `var(--accent)` (sign green), `var(--amber)` (warning), `var(--red)` (emergency/supply air line is red), `var(--blue)` (service air line is blue), `var(--ok)`. Always give shapes an explicit fill. SVG uses `viewBox` + `width="100%"`; must look right at 390 px wide and never cause horizontal page scroll. Keep label font-size ≥ 11 (in viewBox units scaled so text is ≥ 11 px at 390 px width).
6. **Accessibility**: every interactive element is a real `<button>`/`<input>` with a text label or `aria-label`; drag interactions must have a tap/click alternative (select item, then tap target); SVGs have `role="img"` and `aria-label`, or are decorative with `aria-hidden`; honour `props.reducedMotion` (no animation when true); never rely on color alone (add text/icons).
7. **Styling**: use existing classes from `app/src/ui/styles.css` (`btn`, `btn primary`, `btn sm`, `card`, `card tint`, `card warn`, `feedback good/bad` + `verdict`, `row`, `stack`, `grid2`, `field`, `toggle`, `tabs` with `role=tab aria-selected`, `small`, `muted`, `num`, `plate`, `ca-tag`, `diamond`). Inline styles only via tokens. No new global CSS.
8. **Size**: keep each widget file under ~450 lines; no new npm dependencies.
