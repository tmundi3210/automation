## 2. The design + sizing picture (Analyst A's substance, carried intact)

### 2a. Silhouette → stitch → colour → detail

### 2c. Sizing + grading math (the part that must be exact)
- **Size set XS–XXL (6)**, unisex **men's-derived block** (broader/straighter), with a published "size down for fitted / true-to-size for oversized" note `[ESTIMATE: MED-HIGH]`.
- **#1 sizing error to avoid:** the tech-pack spec is **FINISHED-GARMENT (flat/half) measurements, NOT body measurements.** Body chest + ease = garment chest; sweaters carry **~4–6" ease**, our soft-boxy fit at the **upper end (~5–6")**. Grade the *garment*, sanity-check vs body charts.
- **Four knit measurements + M base (FINISHED, inches)** `[ESTIMATE: from public US sweater charts + 5–6" ease, MED-HIGH]`: **Chest 42" full** (21" flat) · **Body length (HPS→hem) 28"** · **Sleeve 35.5"** · **Bottom hem 20" flat**. Secondaries: shoulder ~18.5", armhole depth ~10", cuff rib ~3.5", hem rib ~2.5–3" `[ESTIMATE: MED]`.
- **Linear grade rule (load-bearing):** **Chest +2"/size · Body length +1.5" · Sleeve +0.75" · Hem +2" · Shoulder +0.5"** `[FACT — standard knit grade band: chest 1.5–2", body 1–1.5", sleeve 0.5–1"]`. **Full-chest run: XS 38 · S 40 · M 42 · L 44 · XL 46 · XXL 48** (cross-checked vs published US charts `[FACT]`). Body length XS 25.5 → XXL 33; sleeve XS 33.25 → XXL 37. **Launch linear; let pop-up returns prove whether a non-linear break at XS/XXL is needed** — don't pre-engineer complexity.
- **The knit-specific interaction (gauge ↔ grade ↔ shrinkage):** a sweater is **knit to a stitch/row count, not cut to a pattern**, so the inch-grade must be **translated into whole wales/courses at production density** before it's programmable (`machines §6` — the programmer's job). Illustrative `[ESTIMATE: arithmetic]`: at ~9 wales/inch finished, +2" chest = +18 wales/panel-side — **a 2" grade is only valid if it's an integer number of wales.** Spec **finished dimensions AFTER relaxation/steaming on a washed swatch** (off-machine reads narrow/long). **Build to the POST-WASH target** (knit slightly larger), with **≤3–5% residual shrinkage** in the PO `[ESTIMATE: MED-HIGH]`. **Per-fibre allowance:** cotton (A1) shrinks most + bags out (rib hems hard, consider compacting/sanforising), merino (A3) mills/relaxes more, acrylic (A2) dimensionally stable but heat-sensitive (can't hard-press). Require **balanced ply to kill spirality** (`yarn §4a`). **Put a tolerance on every point** (e.g. chest ±0.5", length ±0.75", sleeve ±0.5") or the grade is decorative.
- **Pop-ups = the fitting lab (highest-value design input the brand owns, the T7 size-curve link):** record per fitted customer the size bought (+ ideally measured chest) → the **distribution of sizes sold = the production size curve** (XS:S:M:L:XL:XXL ratio). In-person try-on **validates grade + ease on the local (~46% Hispanic) body population** (don't assume the national chart fits the local curve), and **directly attacks the ~24% online return rate** (size is the #1 apparel return reason; online ~24% vs in-store ~6%). **Loop every drop:** pop-up curve → adjust grade/ease + production ratio → next drop.

## 3. The Flux pipeline (Analyst B's substance, carried intact) — and how it bolts onto A

### 3a. What Flux is in this pipeline (the framing that prevents the expensive mistake)
Flux sits **upstream of the programmer**, at the *front* of `machines §5`'s "generative design → simulation → virtual-sampling" chain — the **idea/look-generation step, not the program.** **It IS** a near-zero-marginal-cost visual-ideation + mood + **content** engine (and the *act of generating* is the marketing). **It IS NOT** a CAD/knit programmer, gauge calculator, grading engine, or a guarantee the rendered knit is knittable — **it will happily render an impossible knit.** A Flux image has **no stitch count, no GG, no yarn count, no measurement, no shrinkage behaviour.** The brand-specific stake: mistaking a Flux image for a spec ships an un-producible tech pack to Ludhiana and burns a **~2–5 wk sampling cycle + dye-lot money** (`yarn §3c`). **Flux de-risks the *idea*; it does not de-risk the *make*.**

### 3b. The eight-slot prompt skeleton (each slot pulls A's vocabulary)
Lead with subject/garment, end with render controls; order matters `[ESTIMATE: method, HIGH]`:
1. **Garment + silhouette/fit** (← A §1c) · 2. **Knit construction + stitch** (← `SCOPE_GLOSSARY §3` + A §1d) · 3. **Gauge look** — fineness rendered as *visible stitch size*, never a number Flux understands (← `yarn §1c`) · 4. **Colour + fibre/blend hand** — Flux renders *hand/sheen*, not fibre identity (← A §1e) · 5. **Styling + model/no-model** (← A §1c) · 6. **Shot type** — pick ONE · 7. **Photography + lighting** — *clean/light/Californian, never alpine* (← `brand_market §3`; state CA light explicitly or Flux gives you Aspen) · 8. **Render controls** — positive-phrased quality + defect avoidance.
The **four constraints (§1) are baked into the slot choices** so generations stay producible-adjacent.

### 3c. Shot type by job (run all three, at different stages)
- **On-model lookbook** → concept selection + content (most sell-y; but hides construction, hands are the #1 defect source, fit is *implied*).
- **Flat-lay / ghost-mannequin** → read actual garment shape/proportion/stitch/colour for spec hand-off (no measurements; proportions visual).
- **Tech-flat / CAD-style front+back** → closest Flux gets to a spec drawing — but an **illustration, not CAD**, not dimensionally accurate; **treat as a sketch to redraw properly.**
**Workflow:** on-model to *choose a direction* (+make content), then flat-lay + tech-flat of the chosen direction to *read it for hand-off*. Appealing shot first, buildable shot second.

### 3d. Parameters + iteration (all numbers `[SNAPSHOT]` — re-confirm on the live API)
- **Guidance (distilled CFG) ~3.0–3.8** (~3.5 balance; higher→tighter adherence/flatter texture, lower→natural texture/looser brief; tech-flats can push 3.5–5) — the key "did it follow my stitch/colour brief" dial. **Steps ~24–32** (diminishing returns past ~32; low end for sweeps, high for finals). **Dims multiples of 32, ~768–1024/side** (portrait 832×1216 on-model / square 1024×1024 flat-lay). **Seed = fix to iterate, sweep to explore.** **Model tier:** schnell for cheap ideation sweeps → dev for the working look → pro for the hero/content final. `[FACT — Flux guides; SNAPSHOT on exact numbers]`
- **Iteration loop (disciplined sweep, not random re-rolls):** (1) broad explore 5–10 seeds same prompt → contact sheet; (2) **lock seed, sweep ONE slot** (stitch, then colour, then fit) — "change one element at a time, keep seed fixed, so you can attribute the change" `[FACT — Flux best practice]`; (3) tune guidance for fidelity; (4) finalize on the good tier; (5) re-render the chosen direction as flat-lay + tech-flat for hand-off. **Logging discipline (non-negotiable):** save **prompt + seed + guidance + steps + model + dims** with every keeper, or "you've made art, not a process."
- **"Negative prompts" don't work on Flux-dev** (guidance-distilled, CFG≈1) — steer away from defects by **positively describing the correct state**: distorted hands → "five separated fingers, hands relaxed/in pockets" or sidestep (hands in pockets / flat-lay / crop out); fake logos/garbled text → "plain unbranded garment, no text, no logos"; **impossible knits → can't be prompted away (a knowledge gap, not a render flag) → caught in human spec review.** Advanced `true_cfg_scale>1` + real negative exists but ~2× compute, rarely needed. `[FACT — guidance-distilled; SNAPSHOT]`
- **Capsule consistency is engineered, not given:** reuse identical **slots 5–8** (styling+shot+lighting+render-controls) across A1/A2/A3, vary only 1–4; force **shared cream/oat/charcoal anchor tokens** (mirrors real shared-dye-lot economics); hold a **seed family**; optionally feed a hero image via **img2img/IP-Adapter/Redux/"context" reference** *if the endpoint exposes it*. **Honest limit:** consistency is a **brand-look goal (achievable), not a spec-identity guarantee (not achievable)** — spec identity comes from the tech pack, not the image set.

## 4. The bridge: Flux image → producible spec (the seam where A and B meet)

This is the load-bearing junction of the whole T8 deliverable — Analyst B's producibility gap maps **exactly** onto the four numbers Analyst A's sizing math + `yarn` supply. **The two files dovetail here with no conflict; B says "Flux can't give these four," A says "here is where they come from."**

**What a Flux image CAN specify (approved direction, usable):** silhouette/proportion *direction*, stitch/texture *intent*, colour *story*/mood, detailing *intent*, styling/content direction. `[ESTIMATE: HIGH]`

**What a Flux image CANNOT specify — the four buildability inputs, each filled by A/`yarn`/swatch** `[ESTIMATE: HIGH; load-bearing]`:
| Buildability input (B §3b) | Why Flux can't give it | Where it comes from (A / yarn) |
|---|---|---|
| **1. Yarn count + fibre + blend ratio** (resultant Ne/Nm, ply) | renders apparent hand/sheen, not a count/fibre | `yarn §1b/§1c` quadruple + live mandi/importer quote |
| **2. True gauge (GG) + stitch density (wales×courses/in)** | "fineness" is a look, not needles/inch | `SCOPE_GLOSSARY §3` + **A §2d** + **measured on a physical PPS swatch** |
| **3. Panel shaping + stitch-count grade** (FF inc/dec, courses, XS–XXL grade *in stitches*) | draws a shape, doesn't conserve stitches or know the grade rule; **renders impossible shaping** | **A §2c/§2d grade rule → translated into whole wales/courses by the CAD programmer** (`machines §6`) |
| **4. Finished measurements + tolerances + shrinkage allowance** | no inches, ease, ±tol, or post-wash behaviour in a pixel | **A §2b/§2d** finished-garment spec, 5–6" ease, ≤3–5% residual shrink, per-fibre, ±tolerances |

**Plus three things Flux actively gets WRONG (human must catch at review):** **impossible knits** (non-stitch-conserving cables, ribs that change wale count, "seamless" joins no linker makes — A3's cable + fashioning marks are the top offenders); **un-payable colourwork** (6-colour jacquard the 2–4 budget can't fund); **pill-prone acrylic surfaces** (a gorgeous brushed-fuzzy A2 render is a return machine — down-rate it for A2 no matter how pretty).

**The translation workflow (B §3c, ending where A's sizing begins):** (1) choose direction from on-model render (bank as content) → (2) re-render flat-lay + tech-flat → (3) **human review vs the 4 constraints + 3 traps** (kill impossible/un-payable/pill-prone *before money moves*) → (4) map intent onto the upstream specs (fibre×count×gauge×weight quadruple `yarn §1b`, stitch from `SCOPE_GLOSSARY §3`, finished-measurement base + grade **A §2**) → (5) **CAD/flat-knit programmer authors the program** (needle actions, FF shaping, **stitch-count grade** — human + machine-specific Shima APEX/Stoll M1plus, never the image) → (6) **physical PPS swatch + sample = ground truth** (measures real gauge/density/shrinkage, confirms ICI pilling ≥3–4 post-wash) → (7) lock tech pack (measurements + tolerances + count/shade + GSM + stitch + trims + AQL) → (8) **pop-up fit calibration sets the size curve** (A §2e — the render never touches this; body data does).

**The one-line rule:** *the Flux image gets you from blank page → approved look + content; the tech pack + PPS swatch + programmer get you from approved look → knittable garment. Never skip the second half because the first half was cheap and pretty.*
