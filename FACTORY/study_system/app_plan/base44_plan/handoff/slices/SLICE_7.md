## SLICE 7 — Media & 3D flashcards (and voice notes on cards)
**Goal.** Cards can carry pedagogically justified generated images and rotatable 3D models, plus voice-note attachments — with a SKIP-by-default doctrine and a hard human clinical-accuracy gate. Default verdict for any card is SKIP: media is a cost, not a garnish. Uses Slice 5's bridge and Slice 0's Secrets/outbox.

**What to build.**
- **P7.0 Doctrine — the earns-its-cost rule** every media request passes before a pixel or credit is spent: **SKIP (default)** — verbal/arbitrary/list-like content (drug names, criteria lists, definitions): text wins on the cost ledger; decoration actively costs learning; the SKIP verdict is recorded with its reason. **2D image** — content is inherently spatial/structural AND the image is designed to signaling/contiguity/coherence; choose the CHEAPEST honest format; ties break cheaper, never richer. **3D model (gated)** — only when ALL THREE hold: genuinely **volumetric** (a 2D projection loses the tested relation), ships **with guidance** (labeled starting viewpoint, constrained camera, a "look for X" cue — never a naked spinning object), and the **cost is justified** on the ledger. Honesty carry: 3D-vs-2D anatomy evidence is MIXED and moderated by learner spatial ability, which this app does not measure [ESTIMATE — domain prior; never state an effect size as fact]. Screens: a "Media" panel on the card editor (CardForm, APP_RECON §4d) showing the verdict (skip / 2D / 3D) with rationale; never auto-attach media to every card; Review renders attached media inline; cards without media render exactly as today. Entities: `MediaAsset` (card_id/concept_id, kind image|image_set|glb|usdz, file ref, role occlusion_source|diagram|flowchart|model, provenance per P7.4, status) and `MediaTask` (async queue row mirroring the VoiceQueue pattern: requested → generating → generated → gate_pending → attached | rejected | failed(reason)). Cross-cutting: **no scheduler exists** [FACT — APP_RECON §3b] until Slice 0/8 — the media queue drains on an explicit "Process media queue" button; all queue reads paginate past the 500-row cap.
- **P7.1 Image pipeline — designed, bridge-generated, human-gated.** Design before prompting: each warranted image gets a role — occlusion SOURCE (maskable regions, exactly one testable structure per region), labeled DIAGRAM (labels adjacent to referents, never a distant legend), or mechanism FLOWCHART — with coherence (no seductive detail) and signaling as the spec; decoration antipatterns rejected at design time. **Generation transport = the Slice 5 Codex MCP bridge, owned by extint — reference only.** Codex can run as an MCP server (`codex mcp-server`) [FACT-source: EXTERNAL_RECON §5]; whether/how it produces raster images is [UNKNOWN] ([METHOD]: one test call through the bridge before this pipeline is built); documented fallback is Ollama's experimental `/v1/images/generations` endpoint [FACT-source: EXTERNAL_RECON via FEATURE_PLAN P5/P7]. The generator model behind the bridge is **[UNKNOWN] and never named or hard-coded** — provenance stores "generator: UNKNOWN" until extint confirms it. Keys live as per-app Secrets called from backend functions [FACT-source: EXTERNAL_RECON §6]. **The owner's three-images-per-concept pattern** [source: FEATURE_PLAN P7]: three VIEWS (front/left/right) when the objective is 3D form (→ multiview input to P7.2) or three STORY FRAMES (before/during/after) for a process — chosen from the objective, not by default. **Clinical-accuracy human gate (hard):** every anatomical/clinical image is banded and screened for hallucination failure modes (wrong count, fused/duplicated anatomy, impossible arrangement, garbled text), then held at `gate_pending` until the owner approves it in a review screen showing image + prompt + checklist. **No image reaches a card without this approval.** On fail: bounded regeneration (change exactly one named prompt field, max ~3 attempts), then manual sourcing or text-only. Throughput never overrides this gate.
- **P7.2 3D pipeline — gate-passed images → Tripo → in-browser rotatable card.** Only 3D-gate-passed content with gate-passed source images (single centered subject, clean background, even lighting, no watermark/collage). **Tripo** [all FACT-source: EXTERNAL_RECON §7]: API-key auth (`TRIPO_API_KEY`), async task flow (create → poll → download) from a backend function; `get_balance()` returns credits. Branches: `image_to_model` (one image) vs `multiview_to_model` (2–4 views, **front REQUIRED**). Branch rule: if 3D was justified BECAUSE all-around structure is the lesson, **multiview is mandatory** — single-image reconstruction fabricates exactly the unseen geometry the learner must study; single-image only for near-symmetric or front-carried subjects. The ×3 pattern maps to front+left+right [FACT-source: EXTERNAL_RECON §7 / FEATURE_PLAN P7]. **Output**: canonical GLB (`base_model`/`pbr_model`); `convert_model` supports GLTF, USDZ, FBX, OBJ, STL, 3MF [FACT-source: EXTERNAL_RECON §7]. Vision Pro forward path = USDZ (Tripo conversion is [FACT-source: EXTERNAL_RECON §7]; Vision-Pro-consumes-USDZ is [ESTIMATE — high confidence; METHOD: developer.apple.com when an AR sub-phase is scoped]); USDZ generated on demand only. **Mesh QC + web budget:** every GLB checked for hallucinated/warped geometry, fused background, missing textures, wrong scale/orientation — regenerated, never shipped wrong; a mobile web-performance budget (face_limit + texture_size caps for smooth rotation on the owner's phone) binds generation params; a model that cannot meet it falls back to 2D. MediaAsset stores file ref and size; the review screen lazy-loads models [FACT — risk named in FEATURE_PLAN P7]. **Render:** Google's `<model-viewer>` web component displays GLB in-browser with one tag [FACT-source: EXTERNAL_RECON §7]; confirm it loads under the deployed app's CSP with one test model before bulk work; three.js GLTFLoader only as fallback. **Cost honesty:** Tripo pricing/credits [UNKNOWN — METHOD: platform.tripo3d.ai/docs/billing or dashboard] — the owner pastes `TRIPO_API_KEY` themself, sets an initial credit budget and per-week task cap, every batch is gated on a live `get_balance()` check; no per-task price is ever assumed.
- **P7.3 Voice notes on cards — capture-now / grade-later handshake (voice owns).** Reuse the EXISTING capture path: MediaRecorder → `UploadPrivateFile` → `VoiceQueue` row at `status:'queued'` [FACT — APP_RECON §4d]. Honesty: that queue has **no consumer in the repo** — rows sit queued forever as shipped [FACT — APP_RECON §4d]; this slice (or Slice 8's agent) finally gives it one, designed by **voice**, not here. Handshake: capture is dumb-and-fast (record, store, enqueue, return — no inline transcription); processing is async batch under voice's queue state machine (queued → transcribed → graded/structured | failed(reason), nothing silently dropped); voice notes take the transcribe-then-structure path (no grading); any note/flashcard **candidates require the owner's confirmation before entering the knowledge base** — voice's binding rule. Media's only additions: card editor and review screen get a "voice note" chip (plays audio, shows transcript once one exists); MediaAsset links note-audio to its card. Transcription engine choice (local vs cloud) stays voice's owner-deferred config flag; if cloud STT is ever enabled, that is voice/extint's consent-gated decision.
- **P7.4 Quality + honesty gates — generated ≠ verified (the provenance contract).** The hard rule, enforced everywhere: **no image and no 3D model ships to a card without the human clinical-accuracy check** — a generative model cannot certify its own anatomy; Tripo cannot certify a mesh's clinical truth; `gate_pending` is a real blocking state and the review screen is the only path to `attached`. Provenance on every MediaAsset (non-optional): machine_generated flag; exact prompt; generator model (confirmed name or literal `UNKNOWN` — never a guess); quality band; clinical-gate outcome (verified_by + date, or `unverified`); for 3D, Tripo task id, branch, QC result. Review screen and any export (Slice 4) display these fields. Honest UI language: unverified assets are labeled "AI-generated — not yet checked"; generated media is never captioned as sourced from a textbook or atlas.

**Acceptance checks.** A verbal-content card requesting media gets a recorded SKIP with reason; no 3D task exists for content that failed the volumetric-and-guided-and-cost test; every attached asset traces to a stored verdict with complete provenance; zero images/models skip the clinical gate; the regen loop is bounded; all-around-lesson models used multiview with a front view; every shipped model passed mesh QC + the mobile budget and rotates in model-viewer; no asset with `unverified` clinical outcome is attached to any card; the two binding UNKNOWNs (bridge generator model; Tripo per-task price) appear as UNKNOWN in stored data and UI; recording a voice note creates the queue row and returns instantly; no candidate card/note enters the knowledge base without owner confirmation.

**Owner approval gates.** Codex-bridge generation rides Slice 5's owner gate (extint); Tripo = `credential_add` (owner-pasted `TRIPO_API_KEY`) + `spend` (credit budget + per-week cap) + `data_export`-class egress approval (source images leave the app to Tripo's cloud) + first-5 3D cards reviewed side-by-side with their 2D versions before any bulk generation [FACT — FEATURE_PLAN P7 gate]; cloud STT for voice notes = voice/extint's consent gate (`credential_add` + egress). No media feature sends data anywhere else, hosts anything public, or spends money outside these gates.

## AMENDMENT (2026-07-10) — 3D provider is MESHY, not Tripo (owner decision at the credential gate)
Everything in P7.2 stands EXCEPT the vendor plumbing, which extint swaps 1:1 (all Meshy facts [FACT-source: docs.meshy.ai], recorded in recon/EXTERNAL_RECON.md §7b):
- Secret: `MESHY_API_KEY` (format `msy-...`), sent as `Authorization: Bearer <key>`. Never create or fill `TRIPO_API_KEY`.
- Endpoints: single image → `POST api.meshy.ai/openapi/v1/image-to-3d` (URL or base64; GLB/FBX/OBJ/USDZ/STL/3MF); multiview → `POST api.meshy.ai/openapi/v1/multi-image-to-3d` (1–4 images; requires `ai_model: meshy-6` or `latest`). Async: create → task id → poll until SUCCEEDED.
- Spend ground truth: `GET /openapi/v1/balance` replaces get_balance(); ALSO read `consumed_credits` off every task response — the first generated model's consumed_credits is the observed per-task cost that seeds the owner's budget + weekly cap. No assumed price, ever.
- Whether the multi-image endpoint designates a "front" view is [UNKNOWN — verify the image-order semantics at build]; the front+left+right convention and the multiview-mandatory branch rule are OUR design constraints and stand unchanged.
- Unchanged: skip-by-default doctrine, mesh QC, web budget + face/texture caps, clinical gate, USDZ-on-demand (native Meshy output), model-viewer render + CSP test, egress data_export gate (source images now leave to Meshy's cloud, not Tripo's).
