## SLICE 6 — Knowledge graph (Graph page: data, meaning, drawing)
**Goal.** A Graph page over the existing Concept/ConceptEdge entities with typed edges, provenance, terminology linking (hover definitions), semantic zoom, honest color encoding, and a staged msi import. Authority split: **kgraph** owns everything the graph IS (schema, integrity, meaning, linking, gating semantics); **viz** owns everything the graph LOOKS LIKE (zoom, layout, color, interaction). Named consumers (kgraph rule: no structure without a reader): (1) this Graph page; (2) Slice 2 planner gating, which reads prereq edges; (3) the existing pipeline prereq check — today the app's ONLY ConceptEdge reader [FACT — APP_RECON §5.5: read once in runPipeline, zero writers, zero renderers, no graph library installed].

**What to build.**

**§1 DATA & MEANING (kgraph governs).**
- **1.1 Schema mapping — reuse, don't rebuild.** The graph is a labeled property graph over the EXISTING entities. `Concept` = typed node; identity = (exam_code, name); attributes bloom, inbde_fk 1–10, inbde_cc 1–56, inbde_cc_section {DTP,OHM,PP}, toefl_section [FACT — Concept.jsonc, direct entity-file read, verified 2026-07-08; stated exception to the APP_RECON-only rule]. `ConceptEdge` = typed edge; closed vocabulary {prereq, part_of, related} already enforced by enum [FACT — ConceptEdge.jsonc]. Directionality fixed at schema level: prereq and part_of directed src→dst, related symmetric (store once; (A,B)=(B,A) is a duplicate). **Fix a live hazard:** ConceptEdge's `type` defaults to `"prereq"` [FACT — ConceptEdge.jsonc default, direct entity-file read, verified 2026-07-08; stated exception to the APP_RECON-only rule] — an edge saved without an explicit type silently becomes a gating edge. Remove the default (or change to `related`); every edge write must state its type explicitly. prereq is reserved for genuinely gating dependencies, never merely-helpful links.
- **1.2 New fields (entity extensions, no new graph entity).** `ConceptEdge` adds: `source` (enum: manual | ingest | msi_import | llm), `method` (free text), `confidence` (0–1), `evidence` (enum: FACT | ESTIMATE | UNKNOWN), `status` (enum: active | quarantined). No edge is created without all five. LLM-inferred or unsourced edges enter as ESTIMATE/quarantined and are excluded from gating until owner-curated to active. `Concept` adds: `gloss` (≤2 sentences), `synonyms` (string array), `taxonomy_role` (small closed enum — vocabulary defined by kgraph, drawn by viz), `high_yield` (integer tier 0–3; 0 = untagged; no high-yield source exists today [FACT — no such field in Concept.jsonc]; populated only by msi import or owner tagging — where absent, the render must NOT fake it). New entity `TermLink`: card_id, span_text, concept_id, match_method (exact | abbrev | fuzzy), confidence, status (auto | verified | rejected).
- **1.3 Integrity invariants (enforced in ONE backend function, `writeEdge`, the sole edge-write path).** On every candidate edge: (a) both endpoint Concepts exist; (b) no duplicate edge (same endpoints+type; related checked both directions); (c) type ∈ closed vocabulary, explicit; (d) **cycle check**: reject any prereq edge that would close a cycle (offer: drop, or downgrade to related); (e) provenance fields complete. All UI edge creation (Library "A is the base of B" from Slice 2, Graph-page edge editor, imports) calls this function. All graph reads paginate past the 500-row cap [FACT — APP_RECON risk 3] — a silently subset map is unacceptable.
- **1.4 msi ingestion contract.** The owner's `tmundi3210/msi` repo exists (TypeScript, branch `claude/learning-os-system-leSN5`) and is *likely* the USMLE-KG project [FACT existence / ESTIMATE purpose — KG_RECON §1]; its contents are UNREAD — nothing here asserts its schema. [METHOD: a future session reads it and writes the field mapping before any import code.] The app accepts imports as JSON/JSONL: nodes `{external_id, name, synonyms[], taxonomy_role?, gloss?, high_yield?, source_citation}`; edges `{src_external_id, dst_external_id, relation ∈ {prereq, part_of, related}, source_citation, confidence}` — relations outside the closed vocabulary must be mapped or dropped by the exporter, never smuggled in. Import is staged, never direct: validate → dedupe against existing Concepts by exam-scoped normalized name → run all 1.3 invariants → unsourced edges quarantined ESTIMATE → owner reviews a sample → commit with `source: msi_import`. Schema conflict to resolve at mapping time: app `exam_code` enum is {INBDE, TOEFL} only [FACT — Concept.jsonc, direct entity-file read, verified 2026-07-08; stated exception to the APP_RECON-only rule]; USMLE content needs an enum extension or an owner-approved mapping — [UNKNOWN] until msi is read.
- **1.5 Terminology linking (hover definitions).** Pipeline over card prompt/answer text: normalize → exact dictionary lookup over names+synonyms (multi-word longest-match) → abbreviation resolution → fuzzy ONLY after exact misses → disambiguate by the card's exam_code → rank; **abstain below a confidence threshold** (default 0.7 [ESTIMATE — tune on a curated sample]): below it, no TermLink, no hover — a confidently wrong definition on a study card is worse than none. Definitions: **authored-glossary fallback is the policy** — glosses are owner-written or LLM-drafted-then-owner-approved into `Concept.gloss`; no external vocabulary's definitions are stored verbatim (every candidate vocabulary's coverage and licensing are [UNKNOWN — METHOD: recon the license page before adoption, then gate G4]). Batch linking runs as a backend function (`linkTerms`) over cards; report precision/abstain-rate on the first 50 links for owner review.
- **1.6 Prerequisite gating handshake (with Slice 2).** This slice OWNS the validated prereq DAG and the gate spec; it CONSUMES per-concept mastery (BKT `bkt_p_mastery` [FACT — exists in LearnerState]) — estimator math is Slice 2's. Gate spec: block only NEW cards of a dependent concept (reviews never blocked) while any active-status prereq's mastery is below threshold; **hysteresis**: unlock at ≥ 0.6 (the diagnosis rule's own number [FACT — APP_RECON §4a rule 2]), re-lock only below 0.5 [ESTIMATE — design default]; **learner override** per concept always available; quarantined edges never gate. The Graph page must SHOW gate state (which nodes are locked and by which edge) — gating is never invisible.

**§2 VIEW (viz governs).**
- **2.1 Semantic zoom — an LOD ladder, not geometric scaling** (per-level budgets [ESTIMATE — tune at gate G3]): **L0 Overview** (~10–15 marks): meta-node headings only — FK areas / CC sections for INBDE, sections for TOEFL, built ONLY from real structure (part_of edges or the FK/CC attributes on Concept [FACT]); concepts lacking both go into an explicit "Unassigned" group — never invent membership. **L1 Clusters** (~50–80): member concepts, short names, cross-cluster edges bundled. **L2 Concepts**: all edge types drawn (prereq arrows, part_of nesting cue, related plain). **L3 Detail**: focused concept + immediate neighborhood + its cards in the side panel. Honest abstraction dominates clean simplification: a meta-node may hide detail but never implies structure the rows don't support. Mental map preserved: node positions persist across zoom, sessions, and data updates; no full re-flow on each change.
- **2.2 Channel-to-meaning map (classify measurement level first).** **Hue = taxonomy_role (nominal)** — vocabulary is kgraph's (dental consulted for FK grouping), capped at what stays CVD-distinguishable, cap ≈6 [ESTIMATE — verify by CVD simulation]; 10 FK areas exceed the cap, hence roles group FKs. **Brightness/luminance = high_yield tier (ordinal)** — quantized to the 4 stored tiers, no smooth ramp; untagged renders neutral mid-lightness, legend says "untagged". **Corner indicator dot = knowledge state** (separate mark): green = known (mastery ≥ 0.6, matching the gate), gray = unasked, red with 2–3 quantized bins = weak — the red/green pair is the exact CVD hazard, so the dot carries a redundant non-color glyph per state (filled check / hollow ring / exclamation). **Never color alone, anywhere:** role gets a secondary channel (shape or label icon); locked-by-gate gets a padlock glyph. **Secondary channels:** node size = card count, font weight for headings, shape for exam/kind; channel budget per node capped — further attributes go to the side panel. Colors emitted as named computed tokens in a perceptual space (OKLCH/HCL), checked against the app's dark theme [FACT — dark-themed app, APP_RECON §1] for WCAG contrast — checked, not asserted; every contrast/CVD number is [ESTIMATE-to-verify] via an actual checker.
- **2.3 Interaction.** Click (or hover, desktop) a linked term — on the Graph page or on card text carrying a TermLink — opens a **thinking-cloud popover**: the concept's gloss (from `Concept.gloss` only; no gloss or sub-threshold confidence ⇒ no cloud — abstain). Mouse-out dismisses. Clicking the cloud's title clicks through to the concept in the catalog/graph, either in-place with a Back affordance restoring the exact prior view, or in a new side column (split view) — both routes required, per the owner's stated interaction. On the graph: hover highlights connections and dims the rest; click opens the side panel (details, cards, gate state, edge editor); search-to-fly-to-node; filters by exam, role, state (interaction vocabulary proven by Obsidian's graph view [FACT-source: help.obsidian.md/plugins/graph via EXTERNAL_RECON §8]).
- **2.4 Layout & render target.** Layered/hierarchical layout for the directed prereq substructure (flow reads as learning order); force-directed for related/part_of context. No graph library is installed [FACT — APP_RECON §5.5] and NO library's API or node-count performance may be asserted — build-vs-adopt is a **prototyped, measured verdict**: render the ~50-concept sample (gate G3), measure pan/zoom smoothness, then commit. SVG at small scale, canvas above a measured node-count threshold. Viewport culling once counts warrant it.
