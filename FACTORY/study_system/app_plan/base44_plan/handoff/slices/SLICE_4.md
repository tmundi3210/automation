## SLICE 4 — Export, ingest folder, WhatsApp nudges
**Goal.** Owner-initiated data export as files, a staged upload→approve→cards ingest path, and opt-in WhatsApp nudges via self-hosted WAHA.

**What to build.**
- **B.1 Local save/export.** No export/download code exists today [FACT — APP_RECON §5.6]. New entity `ExportJob {scope, formats, status, file_refs, created_date}`; Settings gains export buttons producing downloadable files: **JSON** per entity (cards+options, notes/decks, concepts+edges = the fundamental units: terms/claims/edge triples — semantics deferred to contenteng, extint moves the bytes), **CSV** for tabular (Revlog, LearnerState, DailyPlan), **JSON chart-data snapshots** (mastery history, planner curves). The exporter **enumerates entities dynamically** rather than hardcoding a list, so later phases can't silently fall out of the export [FEATURE_PLAN P4 risk c]. Exports must page past the 500-row caps (S0.3) — an export that truncates is worse than none. `.apkg` stays out of scope (off-repo worker's job today [FACT — APP_RECON risk 2]; live push in Slice 3 supersedes it). Gate: `data_export` — export is owner-initiated by design, and the round-trip check (owner inspects files for completeness) is the acceptance test.
- **B.2 Upload/ingest folder.** A Library upload zone (today the only upload is the single voice file [FACT — APP_RECON §5.7]) feeding a staged pipeline: file → proposed units/cards → **owner approves** → cards created. extint owns only transport + job reliability (upload via the platform's private-file mechanism, an ingest job record with statuses, resumable failure, no silent drops); decomposition/lint is contenteng's authority — its comprehension gate says no card is minted from un-understood text [FACT — SPECIALIST_RECON §5]; item quality of generated cards is qcraft's. Text-first only (pasted text, clean text files); scanned-PDF OCR is a flagged later add-on — no specialist owns parsing below the TOC [FACT — SPECIALIST_RECON gap 5]. Gate: owner approves the first 20 ingested cards by hand before bulk ingestion unlocks.
- **B.3 WhatsApp nudges via WAHA — off by default.** Boundary: WAHA is a self-hosted Docker container (`devlikeapro/waha`, port 3000) wrapping WhatsApp Web; sessions authenticate by QR scan; lifecycle STOPPED→STARTING→SCAN_QR_CODE→WORKING; send = `POST /api/sendText` `{session, chatId: "<phone>@c.us", text}`; free Core = 1 session, text-only; Plus (paid) adds media/multi-session, prices [UNKNOWN — METHOD: waha.devlike.pro/#pricing] [all FACT-source: waha.devlike.pro docs via github.com/devlikeapro/waha-docs + README]. Topology: Base44 backend must reach the owner's WAHA over HTTPS; exposure method (tunnel/VPN/port-forward) [UNKNOWN — METHOD: decide from the owner's home-lab setup] — whatever is chosen passes the `host_public` gate before anything is reachable from the internet. Auth: WAHA API key in a Secret, sent server-side only. Reliability: sends are non-idempotent POSTs → outbox + idempotency key (one nudge per (date, nudge_type); WAHA-side dedup support [UNKNOWN], so dedup is app-side pre-send); send only when session state is WORKING — otherwise breaker open, surface "session needs QR re-scan," never hammer. Nudge wording is a habit cue, never punishment (engage's non-punitive rule). [SIGNAL] WAHA automates WhatsApp Web unofficially; account-ban risk exists — feature ships opt-in, off by default, spare-number recommendation surfaced.

**Acceptance checks.** An export round-trip contains every entity with full row counts (no truncation); an ingest job that fails mid-way resumes without duplicate cards; no card enters the Library without the owner's approval click; with the WAHA session not WORKING, zero sends are attempted and the UI says why; exactly one nudge per (date, nudge_type) even across retries.

**Owner approval gates.** `data_export` (round-trip inspection); first-20-cards ingest approval before bulk; `credential_add` (WAHA key), `host_public` (WAHA exposure), `external_send` + explicit ban-risk opt-in (owner, per FEATURE_PLAN P4 gate), `spend` if WAHA Plus is ever purchased.
