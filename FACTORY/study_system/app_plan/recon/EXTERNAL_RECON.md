## 1. OLLAMA CLOUD

- What it is: [FACT-source: https://docs.ollama.com/cloud (docs-source mirror: github.com/ollama/ollama/blob/main/docs/cloud.mdx)] "Cloud models" run the same Ollama API/tooling but are offloaded to Ollama's cloud service, so large models run without a local GPU; local tools keep working unchanged.
- Sign-up / login: [FACT-source: same] Cloud models require an ollama.com account; from the terminal run `ollama signin` (also `ollama signout`; confirmed in docs/cli.mdx). Once signed in, local commands (`ollama run gpt-oss:120b-cloud`) and local endpoint calls (`http://localhost:11434/api/...` with a `-cloud` model) are auto-authenticated [FACT-source: docs/api/authentication.mdx].
- App login: [UNKNOWN] whether the desktop app UI itself offers sign-in (reachable docs only document `ollama signin`; the app pages don't mention accounts). [METHOD] open https://ollama.com/blog/cloud-models and app Settings on macOS/Windows.

- Base URLs: [FACT-source: docs/api/introduction.mdx] native API local `http://localhost:11434/api`, cloud `https://ollama.com/api` (ollama.com acts as a remote Ollama host).
- OpenAI-compat endpoint: [FACT-source: docs/api/openai-compatibility.mdx] `/v1` surface supports `/v1/chat/completions` (streaming, tools, JSON mode, vision, reasoning_effort), `/v1/responses`, `/v1/completions`, `/v1/models`, `/v1/models/{model}`, `/v1/embeddings`, experimental `/v1/images/generations`. Local base `http://localhost:11434/v1/` (api_key required but ignored). [FACT-source: docs/integrations/droid.mdx in same repo] cloud OpenAI-compat base URL `https://ollama.com/v1/` with `OLLAMA_API_KEY`.
- List cloud models: [FACT-source: docs/cloud.mdx] `curl https://ollama.com/api/tags` (native) — and `/v1/models` on the OpenAI surface [FACT-source: docs/api/openai-compatibility.mdx]. Catalog page: https://ollama.com/search?c=cloud [FACT-source: docs/cloud.mdx].

## 2. ANKICONNECT

Canonical repo/docs: https://git.sr.ht/~foosoft/anki-connect (egress-blocked here; verified via full v6 README mirror github.com/ankiultimate/anki-connect + search snippets of the sourcehut page).
- Install: [FACT-source: https://git.sr.ht/~foosoft/anki-connect README] Anki → Tools → Add-ons → Browse & Install → code **2055492159** (AnkiWeb: https://ankiweb.net/shared/info/2055492159) → restart Anki. Anki must be running; server answers on **http://127.0.0.1:8765** (POST JSON `{action, version: 6, params, key?}` → `{result, error}`).
- addNote / addNotes: [FACT-source: same] `addNote` takes `note: {deckName, modelName, fields, tags, audio/video/picture (filename + data|path|url)}`; returns note id or null. `options.allowDuplicate` (bool), `options.duplicateScope` ("deck" etc.), `options.duplicateScopeOptions` {deckName, checkChildren, checkAllModels}. `addNotes` takes an array; returns array of ids (null per failed note). `canAddNotes` / `canAddNotesWithErrorDetail` for pre-validation.
- Deck/model handling: [FACT-source: same] `deckNames`, `deckNamesAndIds`, `createDeck`, `changeDeck`, `deleteDecks`, `getDeckStats`; `modelNames`, `modelFieldNames`, `createModel`, template/styling actions.
- Scheduling / review-frequency influence: [FACT-source: same]
  - Deck options: `getDeckConfig` / `saveDeckConfig` (config JSON includes `new.perDay`, `rev.perDay`, lapse settings, ease `initialFactor`), `setDeckConfigId` / `cloneDeckConfigId` to assign presets.
  - Per-card: `setDueDate` (e.g. "3-7" random range), `forgetCards` (reset to new), `relearnCards`, `answerCards` (programmatic review answers), `getEaseFactors`/`setEaseFactors`, `suspend`/`unsuspend`, `areDue`, `getIntervals`; stats: `getNumCardsReviewedByDay`, `cardReviews`, `getReviewsOfCards`, `insertReviews`.
  - FSRS: [FACT] the AnkiConnect README documents NO FSRS-specific action (grep of full v6 README: zero hits). FSRS is configured in Anki itself: enable per-collection, set **desired retention** (default 90%; the modern equivalent of SuperMemo's forgetting index) and optimize parameters per preset in Deck Options [FACT-source: https://docs.ankiweb.net/deck-options.html (docs-source mirror: github.com/ankitects/anki-manual src/deck-options.md)]. So the app can influence workload via perDay limits + setDueDate/forgetCards through AnkiConnect, but desired-retention/FSRS params must be set in Anki's UI. [UNKNOWN] whether saveDeckConfig round-trips FSRS fields present in modern config JSON — [METHOD] call getDeckConfig against Anki ≥23.10 and inspect keys.
- Security: [FACT-source: same] binds 127.0.0.1 by default (change via `webBindAddress` config / `ANKICONNECT_BIND_ADDRESS` env); CORS allowlist `webCorsOriginList` (localhost trusted by default; untrusted origins trigger an in-Anki permission popup / `requestPermission` action); optional `apiKey` config → clients must pass `key` in each request body.

## 3. GOOGLE CALENDAR API (+ "Google Reminder")

- Create events: [FACT-source: https://developers.google.com/workspace/calendar/api/guides/create-events + /api/v3/reference/events/insert (via search snippet; domain egress-blocked here)] `events.insert` on calendar (e.g. `calendarId=primary`) with `summary`, `start`/`end` (dateTime+timeZone), etc.
- Reminders/notifications: [FACT-source: https://developers.google.com/workspace/calendar/api/concepts/reminders (via search snippet)] per-event: set `reminders.useDefault=false` + `reminders.overrides[]` with `method: "email" | "popup"` and `minutes` 0–40320 (4 weeks); max 5 overrides per event. `sendUpdates` param controls attendee notification emails on insert/update [FACT-source: events/insert reference].
- OAuth: [FACT-source: https://developers.google.com/workspace/calendar/api/auth (via search snippet)] user-data access requires OAuth 2.0; write scope `https://www.googleapis.com/auth/calendar` (narrower: `.../auth/calendar.events`). No API-key-only access for private calendars [FACT].
- "Google Reminder" API: [FACT] there is no public Google Reminders API. Google migrated Assistant/Calendar Reminders into **Google Tasks** in 2023 [FACT-source: https://workspaceupdates.googleblog.com/2023/06/assistant-and-calendar-reminders-automatically-migrating-to-tasks.html]. Supported alternatives: (a) Calendar events with popup/email reminder overrides (above), or (b) **Google Tasks API** (`tasks.insert`) — caveat: Tasks `due` records date only; "the time portion of the timestamp is discarded... it isn't possible to read or write the time that a task is due via the API" [FACT-source: https://developers.google.com/tasks/reference/rest/v1/tasks (via search snippet)]. For timed notifications, use Calendar events.

## 4. WAHA (WhatsApp HTTP API)

- What it is: [FACT-source: https://waha.devlike.pro/ + docs source github.com/devlikeapro/waha-docs] Self-hosted REST API wrapper around real WhatsApp Web sessions; ships as a Docker image (`devlikeapro/waha`); 3 engines: WEBJS (browser), NOWEB (Node websocket), GOWS (Go websocket) [FACT-source: github.com/devlikeapro/waha README].
- Run: [FACT-source: waha-docs quick-start] `docker run -it --rm -p 3000:3000 devlikeapro/waha`; `init-waha` generates `.env` with dashboard user/password and an **Api Key** used to authenticate API calls; Dashboard + Swagger UI included.
- Sessions/QR: [FACT-source: waha-docs sessions] `POST /api/sessions` creates (and by default starts) a named session; lifecycle STOPPED → STARTING → `SCAN_QR_CODE` → WORKING/FAILED; fetch QR via `GET /api/{session}/auth/qr` (binary, base64 via Accept: application/json, or raw); pairing-code login also supported; re-fetch QR each `session.status: SCAN_QR_CODE` event.
- Send message: [FACT-source: waha-docs send-messages] `POST /api/sendText` body `{"session":"default","chatId":"<E164-digits>@c.us","text":"Hi"}`; options `reply_to`, `mentions`, `linkPreview`.
- License/editions: [FACT-source: github.com/devlikeapro/waha README + site (via search snippet)] Core is free/open (1 session, text-type sends); **Plus** (paid) adds media (images/files/voice/video), unlimited/multiple sessions per container, security extras; PRO tier exists. ## 6. BASE44

All below [FACT-source: docs.base44.com pages (via search snippets; domain egress-blocked here)] — [METHOD] confirm in-app before building.

- Automations: backend functions can run on schedules or on DB events (create/update/delete records) (same page).
- Integrations (3 levels): built-ins (InvokeLLM, SendEmail), OAuth **connectors** (Notion, Slack, Google Workspace...), and raw **external API calls from backend functions using per-app Secrets** (https://docs.base44.com/Integrations/Using-integrations).
- User-provided API keys: yes — store keys as per-app **Secrets** (env vars) and call the external API from a backend function; external services don't allow Base44 to access your credentials automatically, you paste them in (same page + https://docs.base44.com/developers/references/sdk/getting-started/third-party-apis). - GitHub sync: 2-way — Base44 edits (incl. prompt-driven) auto-commit to the repo; pushes to GitHub reflect back into Base44; requires **Builder plan or higher** (https://docs.base44.com/developers/app-code/local-development/github + base44.com/blog/base44-github-integration).

## 7. TRIPO (tripo3d) API — image → 3D

- Official docs: https://platform.tripo3d.ai/docs/generation (egress-blocked here); facts below from the vendor's official Python SDK (PyPI `tripo3d`, repo github.com/VAST-AI-Research/tripo-python-sdk docs/API.md) [FACT-source: https://pypi.org/project/tripo3d/ + that repo].
- Auth: API key (`TRIPO_API_KEY` env or constructor); task-based async flow: create task → poll/wait → download outputs; `get_balance()` returns credit balance [FACT-source: SDK docs].
- Single image: `image_to_model(image=...)` — one reference image; params: model_version (default "v2.5-20250123" in SDK; newer versions exist — v3.0/v3.1/Turbo per vendor announcements [SIGNAL, verify]), texture, pbr, texture_quality standard|detailed, texture_alignment, face_limit, quad, smart_low_poly [FACT-source: SDK docs].
- Multiview: `multiview_to_model(images=[front, back, left, right])` — up to **4 views; front REQUIRED, back/left/right optional** (i.e., 2–4 images) [FACT-source: SDK docs; matches fal.ai's hosted variant "2–4 reference images" [SIGNAL]].
- Output formats: task output/download is **GLB** (`model.glb`, `base_model`, `pbr_model`) [FACT-source: SDK docs download_task_models]; `convert_model(format=...)` supports "GLTF", "USDZ", "FBX", "OBJ", "STL", "3MF" (+quad, face_limit, texture_size/format) [FACT-source: SDK docs].
- Web viewer: [FACT-source: github.com/google/model-viewer (packages/modelviewer.dev data: "glTF/GLB models are supported")] Google's `<model-viewer>` web component renders glTF/GLB in-browser (three.js-based loader, DRACO/KTX2 supported) — so Tripo GLB output can be displayed in a web app with one HTML tag; three.js GLTFLoader is the general-purpose alternative [FACT].
