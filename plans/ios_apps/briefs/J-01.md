## Hard rules
1. Scaffold only. The app shows one screen with the word "Journal". The three Shared modules each hold one placeholder file.
2. Never print a secret. Check with `[ -z "$ANTHROPIC_API_KEY" ] && echo "ANTHROPIC_API_KEY unset" || echo "ANTHROPIC_API_KEY SET"` and the same line for `ANTHROPIC_AUTH_TOKEN`. If either says SET, stop and tell Talwinder. Never run `gh auth token` or anything with `--show-token`.
3. Never edit or regenerate `project.pbxproj`. That means no XcodeGen, Tuist or xcodeproj gem. Linking and target settings are done by Talwinder in Xcode (step 6).
4. Ask Talwinder before anything that leaves the Mac (the push) and before deleting anything.
5. Do not touch `~/Projects/jeet-ios`. Keep `docs/jeet-reuse-report.md` from R-01. Do not start J-02 or any other task.

## Steps
1. **Preflight.**
   - Run the rule-2 check.
   - Run `xcode-select -p; xcodebuild -version; xcrun simctl list runtimes | grep -i ios`. If xcode-select points at CommandLineTools, prefix commands with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. If Xcode asks about a license or first-launch components, ask Talwinder to open Xcode once and accept. If no iOS runtime is listed, ask Talwinder to install one (Xcode > Settings > Components).
   - Run `xcrun xctrace list devices` and note the iPhone's iOS version (in brackets after its name). Xcode's major version must be at least the iPhone's iOS major version. If it isn't, Talwinder updates Xcode before step 7.
   - Confirm `docs/jeet-reuse-report.md` exists; if not, R-01 has not run: stop and say so.
2. **Journal project.** If `Journal/Journal.xcodeproj` does not exist, ask Talwinder to create it:
   - In Xcode: File > New > Project > iOS > App.
   - Product Name: Journal. Team: the Personal Team.
   - Organization Identifier: a unique reverse-DNS such as `com.tmundi`; write it down, since the bundle ID becomes `com.tmundi.Journal`.
   - Interface: SwiftUI. Language: Swift. Testing System: None. Storage: None. Host in CloudKit: off.
   - In the save dialog, select the `mundi-apps` folder itself (Xcode creates `Journal/`) and untick "Create Git repository on my Mac".
   - If it was saved one level too deep, move it to `~/Projects/mundi-apps/Journal/` with Xcode closed.
   - If `Journal/.git` exists, show `git -C Journal log --oneline` and, with Talwinder's OK, remove `Journal/.git`.
3. **Git.**
   - Run `git init -b main`.
   - `.gitignore`: `.DS_Store`, `build/`, `DerivedData/`, `xcuserdata/`, `*.xcuserstate`, `.build/`, `.swiftpm/xcode/xcuserdata/`.
   - If `git config user.email` is empty, ask Talwinder for name and email and set them in this repo only (no `--global`).
4. **Shared package.** Write `Shared/Package.swift` with exactly this content:
   - `// swift-tools-version: 6.2`
   - `name: "Shared"`
   - `platforms: [.iOS(.v26)]`
   - Products: `.library(name: "Storage", targets: ["Storage"])`, `.library(name: "Notifications", targets: ["Notifications"])`, `.library(name: "Export", targets: ["Export"])`.
   - Targets: `.target(name: "Storage", path: "Storage")`, `.target(name: "Notifications", path: "Notifications")`, `.target(name: "Export", path: "Export")`. Paths are relative to `Shared/`; there is no `Shared/Sources/`.
   - One placeholder file each: `Shared/Storage/Storage.swift`, `Shared/Notifications/Notifications.swift`, `Shared/Export/Export.swift`.
   - Check with `cd Shared && swift package dump-package`.
5. **Workspace.** Write `mundi-apps.xcworkspace/contents.xcworkspacedata`: an XML `Workspace version = "1.0"` with two `FileRef` entries, `group:Journal/Journal.xcodeproj` and `group:Shared`. Check with `xcodebuild -list -workspace mundi-apps.xcworkspace`; it should list Journal and the Shared schemes.
6. **Talwinder's Xcode step.** Ask Talwinder to:
   1. Close the Journal project window.
   2. Open `~/Projects/mundi-apps/mundi-apps.xcworkspace`, and always open the workspace from now on. If Shared doesn't appear in the navigator, drag the `Shared` folder in.
   3. Click the blue Journal project, then target Journal > General: set Minimum Deployments to iOS 26.0. Under "Frameworks, Libraries, and Embedded Content", click +, pick Storage, Notifications and Export, then Add.
   4. Press Cmd-S and say done.
   Then:
   - Check that `xcodebuild -workspace mundi-apps.xcworkspace -scheme Journal -showBuildSettings | grep IPHONEOS_DEPLOYMENT_TARGET` shows 26.0.
   - Replace ContentView's body with `Text("Journal")`, add `import Storage`, `import Notifications` and `import Export` to prove the links, and change nothing else in `Journal/`.
7. **Build script.** Write `scripts/build-all.sh` and run `chmod +x` on it.
   - It starts with `#!/bin/bash` and `set -euo pipefail` and runs from the repo root.
   - For each scheme that `xcodebuild -list -workspace mundi-apps.xcworkspace` shows for Journal and the Shared package, it runs `xcodebuild -workspace mundi-apps.xcworkspace -scheme <S> -destination 'generic/platform=iOS Simulator' -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO -quiet build`. Those schemes are either Storage, Notifications and Export, or one `Shared-Package`; use what is listed.
   - It stops with "BUILD FAILED: <scheme>" on any error and ends with "BUILD OK: Journal + Shared, 0 errors". Later tasks add the Reader.
   - Run it until it prints BUILD OK.
8. **Layout doc.** Write `docs/repo-layout.md`:
   - the folder tree;
   - what each Shared module is for and which task fills it (Storage J-03, Notifications J-06, Export J-09; the Reader later adds Speech, LLM, Gap and Scheduling);
   - the Reader slot (`Reader/`, task R-09);
   - a reserved slot for a later learning-system app, which keeps its own spaced-repetition engine and does not use `Shared/Scheduling/`;
   - the test rule: `tests/` holds Xcode unit-test targets added to the workspace by Talwinder in Xcode (SwiftPM test targets can't live outside `Shared/`);
   - the iPhone's exact iOS version from step 1;
   - "always open mundi-apps.xcworkspace".
9. **Run on the iPhone.** Coach Talwinder through these steps:
   1. Unlock the phone, connect the cable, tap Trust and enter the passcode.
   2. In Xcode's top bar, pick the iPhone as the run destination and wait for "Preparing" to finish.
   3. If Xcode says Developer Mode is off: on the phone, Settings > Privacy & Security > Developer Mode > On > Restart, then tap Turn On after the restart.
   4. Press Cmd-R.
   5. If the phone says Untrusted Developer: Settings > General > VPN & Device Management > the Apple ID under Developer App > Trust, then press Cmd-R again.
   6. If signing says the bundle ID is taken, change it under Signing & Capabilities.
   Done when the app opens showing "Journal".
10. **Commit.**

    - `git ls-files -s | grep ^160000` must print nothing.
    - `git ls-files Journal | head` must list the project files.
    - `docs/jeet-reuse-report.md` must be in the commit.
11. **Push to the private remote.** The repo already exists and is empty, and `gh` is already logged in, so skip any create or login step.
    - Optional check: `gh auth status` should show account tmundi3210. Never run `gh auth token` or anything with `--show-token`.
    - Run `git remote add origin https://github.com/tmundi3210/mundi-apps.git`.

    - Check that `gh repo view tmundi3210/mundi-apps --json visibility -q .visibility` prints PRIVATE.
