### salience_heavy — Attention-Map & Linking Engine
- **What to build (concrete):** A `salience.score(node)` service pulling four obtainable public signals — Google Trends search interest, platform follower/subscriber counts, news/GDELT article volume, Wikipedia pageviews — each min-max scaled to [0,1] per pull-batch, combined as a weighted geometric mean (default 0.3/0.25/0.25/0.2, frozen per run). Every score carries `{source, timestamp, access_method}`. A **dual track**: raw mass-salience and a normalized track (÷ population / baseline, or z-score) — never mixed in one ranking. A **region→niche→top-5 expander**: closed single-parent hierarchy (Region → Sub-region → Interest-domain → Sub-niche), seeded at the most salient node, expanded over a priority frontier in strictly decreasing salience under `depth≤4, breadth≤8, top_k=5` + long-tail cutoff → finite, deterministic rebuild.
- **Key details / mechanisms:** **Medium-tier as a measured variable.** Per niche, fit the rank-size (Zipf) curve, pre-register head/medium/tail bands, compute `opportunity = under_served × reachable × addressable_value` (`under_served = 1 − saturation`; `reachable` = channel access at acceptable cost; `addressable_value = size × conversion × value_per_member`); report which band actually peaks. **Geo-relevance link gate:** resolve mentions to canonical ids (transliteration-aware), join on typed `(type,value)` tags so `PLACE:punjab ≠ TOPIC:punjab`, score relatedness (ESA cosine + PMI) only to *rank*, then *license* via the boolean geo/topic predicate; spurious-link guard vetoes irrelevant-but-related joins; arity hard-enforced to {2,3} with triad closure.
- **How it connects:** Inputs — public signals from ingest + reaction/hype/bot signals (saturation + freshness). Outputs — ranked salience map, per-niche tier verdict, validated 2-3 entity scenes (relation type, direction, link-strength, provenance) to GENERATE; the brain consumes the FP1 screen + backtest hooks.
- **v1 vs later:** v1 — 4-signal salience, one diaspora bridge set (Punjab↔IN/CA/UK/US), top-5 expander, opportunity score, predicate-gated arity-2 links. Later — attention half-life → staleness re-pull, scale-free diffusion, threshold recalibration from outcome feedback, arity-3 triads.
- **Make-it-real must-haves:** a frozen signal-weight + tier-band config per run (provenance + reproducibility); a typed-tag entity registry with the geo-relevance predicate table.

### signal_heavy — Signal & Dense-Brief Layer
- **What to build (concrete):** (1) a calibrated **inauthenticity estimator** emitting `P(inauthentic|public signals) ∈ [0,1]` + uncertainty interval + provenance (never boolean); (2) a **genuine-vs-manufactured hype check** counting independent origins after provenance dedup, certifying `genuine` only at `≥N`; (3) a token-budgeted **dense-brief emitter** in a fixed pipe/KV grammar with a leading `schema_hint`.
- **Key details / mechanisms:** estimator inputs = five families: account (age/handle-entropy/completeness), templated-text (MinHash/SimHash near-dup), timing (burst/synchrony entropy), network (co-engagement density, k-core), engagement-mismatch (like:comment:reach vs baseline); fuse via decomposable logistic/GBM, calibrate Platt→isotonic against a versioned labeled CIB benchmark; validate ECE + reliability curve + FPR/TPR; record which platform-internal signals (IP/device/login-graph) were unavailable/proxied. Hype: collapse cross-posts/screenshots to provenance seeds (content-hash + first-seen), reduce correlated/common-method sources to distinct origins, discount bot-risk + saturation, apply `≥N` gate independent of volume. Brief grammar (one line/item): `B1|topic=<id>|auth_p=0.18[0.10,0.27]|unavail=ip,dev|hype=manuf|orig=2/N3|virality=broadcast|sent=-0.4|ent=[e1,e2]|geo=<region>|salience=0.71|claim:<txt>~v:obs|conf=0.62` with an abbreviation key paid once + verifiability tags (`v:obs|v:derived|v:proxied`).
- **How it connects:** Inputs from ingest (raw reactions + crawl provenance) + salience (region/niche/tier, candidate entities). Outputs to salience (auth-discounted hype + entity hints to weight scene selection) and creative (consumes the dense brief verbatim). Controller reads `auth_p, hype, orig, conf`.
- **v1 vs later:** v1 — account+templated-text+timing features, Platt calibration, exact-hash dedup, fixed N, single-line brief + round-trip/coverage audit. Later — network/structural-virality features, isotonic + adversarial-decay refit, Bass-curve + search-interest corroboration, governed/versioned N, learned rate-distortion point.
- **Make-it-real must-haves:** a versioned labeled CIB benchmark for calibration/validation; a field-set + decision contract fixing the entropy floor.

### orch — Controller & Orchestration Architecture
- **What to build (concrete):** a **DAG controller** `ingest → salience → entity_link → signal{authenticity, hype} → dense_summary → creative_brief → compliance_gate → emit`. `signal` is a bounded fan-out/join (authenticity + hype in parallel, timeout barrier, confidence-weighted blend). The control plane is a thin scheduler: typed blackboard state (write-owner per field), rule-based router, per-node circuit breakers, token-budget accountant, trace emitter. `compliance_gate` is the **sole predecessor of `emit`** (edge-permission matrix at compile time; static cycle/edge check every deploy).
- **Key details / mechanisms:** routing rule-based first (0ms, interpretable), LLM-judge router only where measured accuracy ≥0.90 justifies the latency. Aggregation = weighted blend (weights from ≥100 held-out examples/agent, version-locked, ECE<0.05). Context budget enforced before each LLM node; overflow forces `dense_summary` (extractive for high-stakes facts). Compliance gate = post-aggregation safety filter over the *final brief* (catches emergent harms), emits `pass | block→human_queue | escalate`.
- **How it connects:** each node reads/writes only its owned blackboard fields via typed schema; `dense_summary` produces the bounded artifact `creative_brief` consumes; the gate produces a single signed, sanitized `EmitPacket`.
- **v1 vs later:** v1 — linear DAG, rule router, parallel signal fan-out, single weighted-blend, gate-before-emit, traces + circuit breakers, offline weight derivation. Later — LLM-judge routing, debate on the brief path, MoE creative gating, adaptive-K self-consistency.
- **Make-it-real must-haves:** cross-session emit seam = an **outbox** (gate writes an immutable schema-validated sanitized packet to a durable queue with idempotency key; downstream *pulls* it — no in-process call across the trust boundary, sanitize at the edge). Bounded improve-loop runs **offline only** (production outcomes → eval regression suite → version-controlled weight/threshold update at a min-interval, gated by canary metrics; never mutates the live controller mid-request).

### reason — Reasoning & Decision Layer
- **What to build (concrete):** a **link proposer + scorer** (abductive generate-and-score): sample N=12-20 candidate links per item via temperature CoT, each `{target, relation, one-line rationale}` as constrained JSON, score with a lightweight **PRM-style verifier** on relevance / non-obviousness / evidential support, keep top 2-3. An **authenticity/hype judge** as a hallucination-detection pipeline: extract atomic claims, NLI-entail each against retrieved evidence, emit `authenticity ∈ [0,1]` (fraction grounded) + `hype ∈ [0,1]` (fraction unsupported/superlative-but-uncited). A **calibrated go/no-go head**: combine link-score + authenticity + hype + scene-coherence into one confidence via a small fitted logistic, temperature-scaled, with a domain-tuned abstention threshold.
- **Key details / mechanisms:** verifier is a separate model from the generator (>80% injected-error catch, <15% FP) so the composer can't grade its own links. Token-saturation budget (N capped at p95 saturation, adaptive: easy→N=4 greedy, hard→full N). Tool-grounding for numeric/date claims, reject-on-mismatch before NLI.
- **How it connects:** link step feeds the composer the top 2-3 typed links + rationales; authenticity/hype produces the two scores the controller weighs; go/no-go turns all signals into one confidence (below threshold → abstain).
- **v1 vs later:** v1 — zero-shot CoT proposer + zero-shot LLM verifier + off-the-shelf NLI + temperature-scaled logistic on a few hundred labels. Later — fine-tuned PRM verifier, difficulty router (≥30% cost cut), debate for contested authenticity calls.
- **Make-it-real must-haves:** a labeled validation set (good/bad links, real/hype items) to fit calibration + measure ECE<0.05; a retrieval/evidence source so authenticity is grounded. *(Confidence is a measured calibration property — ECE on held-out labels — not a model self-report.)*

### psych — Ethical Resonance Playbook
- **What to build (concrete):** a **4-driver scene generator** linking relatable things to scenes scored on identity-fit, belonging, emotion, surprise (the genuine drivers of healthy sharing); favor self-relevant content + high-arousal positive emotion (awe, amusement, pride) over anger/outrage. A **safe-lanes whitelist**: (1) creator's own persona/self-deprecation, (2) consented subjects, (3) clearly-signposted parody, (4) shared-experience/identity content; block the covert-outrage-about-real-people lane. A **sentiment dashboard** correcting for vocal-minority bias before any "audience loves/hates this" call.
- **Key details / mechanisms:** driver scoring (require self-relevance + one positive high-arousal emotion before publish; surprise = mild expectancy-violation, not shock). Identity resonance leads with shared in-group experience, not out-group contrast (which invites backlash). Honest sentiment correction: weight by reach not comments; saves/shares/watch-time > comment sentiment; track a stable panel. Disclosure: parody/persona cues labeled, not hidden.
- **How it connects:** driver scores tell you which segment a scene targets + how to frame it (lead emotion, expectancy-violation size, in-group vs out-group); the safe-lanes filter gates which subjects/topics are eligible before framing.
- **v1 vs later:** v1 — manual 4-driver checklist + safe-lane whitelist + share/save-weighted sentiment read. Later — lightweight per-segment resonance model, A/B on emotion lead, longitudinal trust tracking.
- **Make-it-real must-haves:** a consent/lane-eligibility gate before any real person is featured; a share-and-save-weighted metric (not comment volume) so design optimizes resonance, not reaction. *(Self-relevance + high-arousal-emotion sharing drivers are well-replicated directionally; measure effect sizes on your own audience.)*
